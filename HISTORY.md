## Synopsis Feature

- ISBNdb synopses added to bibnotes (2026-08-02): `pdf_annot/synopsis.py::format_synopsis_callout` converts a `<pdf_id>.txt` (from `haddolib`’s `isbndb_synopsis.py`) into an `>[!abstract] Synopsis (ISBNdb.com)` callout. Raw text is canonicalized (strip/drop blank lines; collapse runs of `<br>`/`<hr>` variants case-insensitively) and rendered as `>`-prefixed paragraphs separated by bare `>` lines, relying on Obsidian lazy continuation to keep a single block. `notes.py::has_synopsis_block`/`ensure_synopsis_block` detect/insert case-insensitively; the existing hand-written synopsis `(Thrangu 2003)` is recognized and left untouched. Placement: below thumbnail span → else below resume-PDF button → else top of body, always with exactly one blank line on each side.
- Not integrated with `sync.py`: insertion is handled only by `tools/fill_synopses.py` (`make fill-synopses`), since fetching via `haddolib` is manual and scanning ~1600 notes on every `make run` was deemed unnecessary. Insertion is permanent (no `--force`); to refresh, delete the callout manually (tool cannot distinguish stale vs intentional edits). `--pdf-id` limits runs for testing.
- New config: `paths.synopses_dir` in `pdf_annot.toml`, never auto-created (even if `create_missing_dirs`), because it is read-only here and absence usually means the ISBNdb export step was skipped; auto-creating would mask the error as mass skips.
- Live tests with `(Johnson 2017a)` and `(Aylward 2021)` exposed paragraph-splitting edge cases (whitespace-separated break tags, leftover per-paragraph artifacts, `<p>` variants); noted in `TODO.md` for cleanup before full-corpus run.

## Page-1 Thumbnails

- Thumbnails added (2026-07-26): `sync.py` renders and inserts a page-1 JPEG thumbnail for new and changed bibnotes whenever `thumbnails_dir` is set in `pdf_annot.toml`; `tools/backfill_thumbnails.py` (`make backfill-thumbnails`) retrofits the existing corpus. Idempotency is decided by whether the JPEG exists on disk, not by the `<span>` text -- deleting a thumbnail file is the signal to regenerate it, so a stale image doesn't silently survive a re-run. `--pdf-id`/`--force` (`make backfill-thumbnail-example`) regenerates one file on demand. Thumbnails are named by `pdf_id`, not `pdf_hash`: hashes are Anima-internal plumbing with no reason to surface in the vault. Rendered via PyMuPDF at 3x the display pixel width for Retina sharpness, JPEG quality 80 (indistinguishable from 90 on text-heavy pages, meaningfully smaller across ~1600 files); display width tuned by eye to 250px. Both are code constants in `thumbnails.py`, deliberately not `env`-configurable. The two workflow buttons are added manually via a Dataview template call and never written by this tool; `notes.py::ensure_thumbnail_header` positions the span accordingly -- directly under the frontmatter if no buttons yet, or below the buttons line (blank line on each side) if they're already there.

## Post-Audit Cleanup

- Filesdump integrity restored (2026-07-24): `make gentree` wrote `tmp/project_tree.txt` while `manifest.lst` included `tmp/project-tree.txt`, so every dump shipped a stale tree -- one predating `resolve.py`, still listing `tests/test_annotations.py` (deleted in A8) and `tools/print_hashes.py` (retired in A9), and unaware of `docs/`, `HISTORY.md` and `tools/time_extraction.py`. The consequence matters more than the typo: A8's adopted remedy for the pruned-dump failure was to cross-check the dump's tree listing against the documents it actually includes, and that check had been reading a frozen snapshot ever since, so it could not have caught anything. The manifest now names the file `gentree` writes. In the same pass `tests/test_fasching_extraction.py` and its fixture were restored to `manifest.lst`, closing the last gap between what the tree lists and what the dump carries, so the suite is now fully accounted for by the manifest; and `AUDIT.md`'s status line was updated to record A10 and to mark that document a frozen record, out of the standard filesdump and not maintained further.
- `NotesDB` retired for `build_notes_index` (2026-07-24): what survived A8's cut was a `Mapping` subclass wrapping a dict and re-exposing the dict interface it already had -- `__len__`, `__iter__`, `__getitem__`, `ids`, `values`, `items` -- of which production consumed exactly `len()` and `.get()`. `notes_db.build_notes_index(notes_root)` now returns a plain `dict[str, NoteInfo]`, mirroring `pdf_registry.build_pdf_index`; `is_controlled_md_name`, `DuplicateNoteIdError` and `NoteInfo` are unchanged. The decision a future session might otherwise reverse by accident: the class's only behaviour of its own was lowercasing the lookup key in `__getitem__`, and that is deliberately not restored -- the one production caller already passes a lowercased id, and no test in the suite ever passed a non-lowercase key, so the guard had no witness and was enforcing nothing. Callers normalize; the module docstring states this and states not to re-add a container. Side effect worth knowing: `notes_db.py` no longer imports `env.py`, since the `from_env` classmethod was the only reason for that dependency, so the module now takes a path exactly as the PDF side does. Four files changed -- `notes_db.py`, `sync.py`, `tests/test_notes_db.py`, and `tests/test_env.py`, whose `test_notesdb_from_env_integration` was dropped rather than ported, two of its three assertions having checked that the class was a class and knew its own root, with the env plumbing it nominally covered already covered by the config tests above it. `README.md`'s production call-path paragraph was corrected in the same pass: it named `NotesDB` and also `PdfRegistry`, a class that never existed at all, in the very paragraph A10 had added so that pathway drift could not go unnoticed.
- `paths.backup_dir` retired (2026-07-24): an aspiration encoded as configuration -- a slot for backups reserved before any backup mechanism existed -- that never acquired a consumer. It outlived A9 and decision D2, whose sweep removed knobs nothing referenced, because `env.py` validated it, `env.py` created the directory under `create_missing_dirs`, and three test files asserted on it; to a grep it looked consumed. That is the shape worth carrying forward: a test asserting on a knob is evidence of use, so dead configuration hides behind its own tests. Removed from the `Paths` model, the `_norm_backup_dir` validator, the `_validate_directories` mkdir block, the flat-key alias table, the `Env` docstring, `pdf_annot.example.toml`, and the three test files; `test_backup_dir_created_when_allowed` went with it, while its sibling `test_temp_dir_created_when_allowed` keeps the directory-creation property covered for the path that is real. Behavioural change, small but visible on disk: a configured backup directory is no longer auto-created. A stale `backup_dir` key left in a live `pdf_annot.toml` is ignored rather than rejected, because the loader copies the `[paths]` section into a Pydantic model that ignores unknown keys. The need this knob gestured at is not lost -- it is `TODO.md`'s standing item to put the vault under version control, which is the real answer and is blocking `LINK_REFACTOR.md`. One artefact is worth preserving as a specimen of the pattern: `tests/test_pdf_to_markdown_e2e.py` carried the comment `# --- FIX: Explicitly set backup_dir=None to satisfy linter ---` above the call, a parameter no code consumed, passed explicitly to quiet a linter, with a note preserving the reason for a fix that was never about anything.

## Production-Readiness Audit

- Production-readiness audit complete (2026-07-21 through 2026-07-24): the `src/pdf_annot/` audit closed with A1-A9 landed and A10 documentation/harvesting complete. Production note writes now go through `atomic_write_file`; sync declines existing notes it cannot safely identify as intact bibnotes; `pdf_mtime` comparison normalizes Obsidian's quoted and unquoted YAML timestamp shapes; and extraction caches page words and superscript regions lazily per highlighted page, reducing the measured 244-PDF full extraction pass from 362.67s to 144.54s. Controlled PDF and bibnote names now share one strict id predicate, registry and diagnostic discovery share one case-insensitive PDF walker, and marker annotation types no longer inflate `pdf_highlights` while Text and FreeText remain deliberately counted as `pdf_textboxes` migration debt. The streamliner has one state machine for both list and NDJSON entry points, accepting both real PyMuPDF tuple annotation types and JSON list shapes. `--dry-run` is now full-fidelity and diverges from a real run only at the one atomic write, so it neither changes notes nor closes the next real run's change gate. Dead freight was removed: Dropbox-relative registry state, legacy filename/hash helpers and dash parsing, inactive config profiles and aliases, the unused `atomic_writes` knob, and the unused hash tool. The dormant `NotesDB` plan/apply layer was retired in favor of the live direct sync path; it is recoverable if a concrete future need arises from commit `615200c` ("A8 first part") via `git show 615200c:src/pdf_annot/notes_db.py` and `git show 615200c:tests/test_annotations.py`. `README.md` now records the current production call path and the source-of-truth philosophy: PDFs are authoritative for highlights and comments, while bibnotes are a useful derived service and extraction is heuristic by design. `AUDIT.md` remains the full evidence ledger; this entry records the durable end state rather than reproducing the audit's development history.

## pdf:// Resolution (Obsidian -> Anima)

- Resolver CLI -- Phase A of the `pdf://` link-resolution contract (2026-07-18): added `src/pdf_annot/resolve.py`, the public interface that maps a `crc32_az7` hash (as it appears in a `pdf://<HASH>` URL host) to a fully-qualified PDF path. This is the pdf-annotations half of the two-project contract frozen in `TARGET_ARCHITECTURE.md` (section 3); Anima consumes it as a subprocess, so the contract is the CLI surface -- stdout, stderr, exit code -- not the Python API. `resolve.py` reuses `pdf_registry.build_pdf_index` and `env.load_env` unchanged and imports nothing heavy (no `fitz`), because per-click subprocess latency depends on import time; verified by inspecting the import chain. It owns only the hash-to-path action: `main()` handles argv and the process exit code, `resolve()` does load-config -> build-index -> scan `index.values()` for a matching `pdf_hash` (case-insensitive, normalized once at the top). Because `build_pdf_index` keys its dict by `pdf_id.lower()` rather than by hash, the lookup is a linear scan over values -- a non-issue at 1600 files, since the folder walk dominates and the in-memory scan is microseconds; re-keying the shared registry was rejected as an out-of-scope change to a working subsystem with other consumers. Strict duplicate handling is inherited verbatim: any duplicate `pdf_id` anywhere in `pdf_dirs` fails ALL resolutions (`DuplicatePdfIdError` caught and formatted), matching section 3.4. The three failure messages (no-match, duplicate, config-error) are declared as module constants so the tests assert against the same strings the code emits, with no drift; two small contract refinements were made here -- the duplicate message lists its paths sorted (walk order is not deterministic across machines), and the config-error message uses `--` rather than an em-dash. Registered the `pdf-annot-resolve` console script in `pyproject.toml` alongside the existing three; the bridge itself uses the `-m pdf_annot.resolve` form and does not depend on the script being installed. Pinned by `tests/test_resolve.py`: five subprocess-level contract tests (success, case-insensitive success, unknown hash, staged duplicate across two folders, missing-config error), each importing the message constants as the single source of truth. Acceptance was run against the real ~1600-file collection: a known hash resolved to its absolute path (exit 0); an unknown hash produced the no-match message (exit 1); a deliberately staged duplicate produced the strict two-path error and was then removed; and the section 3.6 config-discovery question was settled empirically -- with `PDF_ANNOT_ENV_PATH` unset, the same known hash resolves from the project root but fails with a configuration error from `/tmp`, confirming that `load_env` locates `pdf_annot.toml` via the current working directory and that section 3.1's "run with CWD = <pdfAnnotationsRoot>" requirement stands as written. With the contract frozen and Phase A accepted, the next locus of attention is Phase B in Anima.
